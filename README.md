# AI 투자위원회 (ai-investment-committee)

성향이 다른 AI 위원 3명이 근거와 함께 투자 의견을 내고, 사람은 **위원장**으로서 누구를 얼마나 믿을지와 판단 기준을 정한 뒤 승인하는 웹 앱입니다. 위원들의 의견은 LLM이 말로 합치지 않고 **Black-Litterman 수식**으로 합칩니다.

- 데모: https://orca-svg.github.io/ai-investment-committee/
- GDGoC DevFest 2026 「Tell the Vision」 · Team 06 Money is Our Life · 주제 경제 · 소통
- 상태: 비교용 low-fi 프로토타입. 데이터는 시드를 고정한 난수로 만든 샘플이며 실제 시세가 아닙니다. 매매도 모의 매매만 합니다.

## 왜 만들었나

여러 AI 에이전트가 매매 전략을 세우고 자동으로 거래하는 시스템은 이미 있습니다. 하지만 대부분 AI가 말로 결론을 합치고 그대로 매매까지 갑니다. 그래서 누가 어떤 근거로 무엇을 주장했는지, 그리고 '저평가 주식' 같은 판단 기준이 무엇이었는지 사람이 확인하거나 고칠 수 없습니다.

이 앱은 세 가지를 바꿉니다.

1. 의견은 투명한 수식(Black-Litterman)으로 합칩니다.
2. 신뢰도와 개념 정의라는 다이얼을 사람이 쥡니다.
3. 사람이 승인한 결정만 모의 매매로 이어집니다.

즉 목표는 자동으로 수익을 내는 것이 아니라 **납득되는 결정**입니다.

## 핵심 기능

| 기능 | 하는 일 |
| --- | --- |
| 의견 듣기 | 가치·모멘텀·리스크관리 위원(Gemini)이 표의 수치를 인용해 종목별 견해와 확신도를 냅니다 |
| 신뢰도 슬라이더 | "얼마나 믿을까요?"를 조절하면 포트폴리오와 위원별 영향력이 즉시 다시 계산됩니다. 이 과정에는 AI 호출이 없습니다 |
| 개념 정의 편집 | 위원의 성향을 '가치주 = PBR 1 미만 그리고 ROE 8% 초과' 같은 규칙으로 드러냅니다. 해당 종목은 코드가 판정하고, 기준을 바꾸면 그 위원에게 다시 묻습니다 |
| 결정 과정 추적 | 누가 어떤 근거로 무엇을 주장했고 결과에 얼마나 기여했는지, BL 수식과 검산까지 보여 줍니다 |
| 승인 · 반려 | 승인하면 모의 매매 기록에 남고, 반려하면 사유를 남깁니다 |

## 사용한 경제학 개념

| 개념 | 이 앱에서의 역할 |
| --- | --- |
| CAPM 균형 수익률(역최적화) | 시가총액 비중에서 역산한 기대 초과수익 π = δΣw_mkt. 아무 의견이 없으면 시장 비중을 그대로 유지합니다 |
| 위험회피계수 δ | 시장 포트폴리오의 기대 초과수익 6% 가정에서 δ = 6% / 시장 분산으로 역산합니다 |
| Black-Litterman | 위원 견해 "π보다 x%p 더/덜 오른다"를 P = eᵢ, Q = πᵢ + x로 넣고 사후 기대수익 μ를 구합니다 |
| 확신도 → Ω (Idzorek식) | 유효 확신도 c = 위원 확신도 × 위원장 신뢰도, Ω = τ·pΣpᵀ·(1−c)/c. 신뢰도가 0이면 그 위원은 반영되지 않습니다 |
| 평균-분산 최적화 | 롱온리, 비중 합 100% 제약에서 wᵀμ − (δ/2)wᵀΣw를 최대화합니다 |
| 표본 공분산 | 월간 수익률의 표본 공분산을 연율화(×12)해서 위험을 계산합니다 |
| 팩터로 정의한 개념 | 가치(PBR·PER·ROE), 모멘텀(12개월·3개월 수익률), 위험(변동성·최대낙폭)으로 위원 성향을 정의합니다 |
| 기여도 분해 | μ − π는 (Q − Pπ)에 선형이라 위원별 기여를 정확히 나눠 더할 수 있습니다 |

```
μ = π + τΣPᵀ (PτΣPᵀ + Ω)⁻¹ (Q − Pπ)
```

## 구조

```
브라우저 (GitHub Pages: public/)
   │  위원별 의견 요청  POST /api/agent-view  (의견 듣기 1회 = 3회 호출)
   ▼
API 서버 (Cloud Run: server.mjs)  ── GEMINI_API_KEY는 Secret Manager에서만 주입
   │  구조화 출력(responseSchema)
   ▼
Gemini API
```

개념 판정, BL 합산, 최적화는 `public/core.js` 한 곳에 있고 브라우저·서버·테스트가 함께 씁니다. 따라서 "누가 해당하는가"와 "어떻게 합치는가"는 LLM이 아니라 코드가 정합니다.

```
server.mjs          정적 파일 + /api/config + /api/agent-view (Gemini REST, 구조화 출력, CORS, 호출 제한)
public/core.js      개념 판정 · Black-Litterman · 롱온리 최적화
public/app.js       화면 로직 (바닐라 JS)
public/api.js       API 주소. github.io에서는 Cloud Run, 로컬에서는 같은 서버
public/index.html   마크업 + CSS
data/sample.json    샘플 데이터 (scripts/gen-data.mjs, 시드 고정 난수)
test/sanity.mjs     BL sanity check
```

**ADK를 쓰지 않은 이유:** 오케스트레이션이 "위원 3명 병렬 호출 → 수식으로 합산"이라는 고정된 구조입니다. 게다가 이 컨셉의 핵심은 "합산을 LLM에 맡기지 않는다"입니다. 그래서 Gemini API(REST, `responseSchema` 구조화 출력)를 직접 호출합니다.

## 로컬 실행

의존성이 없어서 `npm install`이 필요 없습니다. Node 22.9 이상이 필요합니다.

```bash
echo "GEMINI_API_KEY=발급받은_키" > .env   # https://aistudio.google.com/apikey
npm start          # http://localhost:4100
npm test           # BL sanity check (견해 없음 → μ = π, w = w_mkt)
```

- 키가 없으면 **오프라인 규칙 모드**로 동작합니다. 즉 위원 견해를 개념 판정 결과에서 규칙으로 만들고, 화면 상단에도 그렇게 표시합니다.
- 모델은 `GEMINI_MODEL`로 고를 수 있습니다. 생략하면 이 키로 쓸 수 있는 최신 Flash 모델을 자동으로 고릅니다.

## 배포와 키 관리

- **화면:** `main`에 push하면 `.github/workflows/pages.yml`이 `public/`을 GitHub Pages에 올립니다.
- **API 서버:** Cloud Run에 배포합니다. 키는 Secret Manager에 두고 환경변수로만 주입합니다.

```bash
gcloud run deploy ai-investment-committee --source . --region asia-northeast3 \
  --allow-unauthenticated --max-instances 2 \
  --set-secrets GEMINI_API_KEY=gemini-api-key:latest
```

- `.env`는 `.gitignore`·`.gcloudignore`·`.dockerignore`에서 모두 제외되어 저장소와 이미지에 들어가지 않습니다.
- 서버는 `https://orca-svg.github.io`에서 온 요청만 브라우저에 허용(CORS)하고, 위원 호출은 IP당 10분에 60회(의견 듣기 약 20번)로 제한합니다.

| 0:00 | 오른쪽 포트폴리오를 본다 | "아직 의견이 없어 시장 비중 그대로" — 시장 비중이 출발점 |
